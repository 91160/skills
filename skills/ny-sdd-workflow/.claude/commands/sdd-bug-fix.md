# /sdd-bug-fix — Bug 修复回环

触发 SDD Workflow 的 **当前需求 bug 修复回环**：G0.4.1 二次判定 → §3.0 通道判断（不新建 REQ/DES，复用 approved 文档）。等价自然语言「这里有个 bug」「XXX 报错」+ 当前正在开发该模块的场景。

## 前置检查

1. 读取项目根目录 `AGENTS.md`。不存在 → 提示「工作流尚未安装，请先 `/sdd-init`」并退出。
2. 读取 `.project/context.md`：
   - 不存在 → 提示「项目尚未启动开发，请先 `/sdd-start`」并退出。
   - 存在 → 记录**倒数第一条 last 字段**作为「原始 last」（回环结束后按此路由）。

## 二次判定（按 AGENTS.md G0.4.1）

按以下规则判定 bug 归属：

| 判定条件 | 场景 | 处理 |
|---|---|---|
| 原始 `last` 在 §3.x 或 §4，**且** bug 描述与 context.md 当前模块一致 | **当前需求 bug** | 直接进入 §3.0 通道判断（bug 修复回环） |
| 原始 `last` 不在 §3.x~§4，**或** bug 与当前模块无关 | **新 bug 工单** | 触发 G2 停车，让用户选择 |
| 无法判定 | 不确定 | 触发 G2 停车，让用户选择 |

**G2 停车时三选一**：
```
【流程冲突确认】
当前 context.md 状态：last = {字段}（{模块名/任务名}）
本次 bug 描述：{$ARGUMENTS}
判定结果：{判定理由}

请选择处理方式：
  A. 强制走当前需求 bug 修复回环（即便归属判定不明，用户确信关联）
  B. 作为新独立 bug 工单（类型=bug，进入 G0.5 → §2.2 新建 REQ/DES）
  C. 取消
```

## 用户选择后的路由

### 选 A → 进入「当前需求 bug 修复回环」（见下方"进入回环"章节）

### 选 B → 进入「新 bug 工单」标准流程
- **退出本命令的回环逻辑**，不读取 phase-coding.md
- AI 重定向到 G0.5 阶段路由（按 AGENTS.md G0.5 表）
- 任务类型设为 `bug`，进入 §2.2 需求分析（C. Bug 修复 模板）
- 后续走 §2.2 → §2.3 → §2.5 → §2.7 → §3 → §4 标准流程，**新建 REQ/DES**
- **更新 context.md**：追加一条记录 `{日期} 新 bug 工单：{现象简述}（用户选择按新工单处理）— last: §2.2 需求分析（下次进入 §2.3 方案设计）`

### 选 C → 取消，保持现状（不修改任何文件）

---

## 阶段执行约束（与 G0.5 一致）

进入 §3.0 通道判断前，AI **必须**先输出 §3.0 的流程声明头作为可见凭证（严格与 `{SKILL_DIR}/rules/phase-coding.md` §3.0 章节顶部声明头一致，**不得简化 prev/next 字段**）：

```
【进入 §3.0 通道判断】
> **流程声明**
> - phase: coding
> - step: 0/11
> - prev: §2.7 功能测试用例设计 / G0.5 阶段路由（已有 approved spec）/ G0.4.1 bug 意图二次判定（当前需求 bug）
> - next: §3.1 加载规范 + 铁律（快速/标准通道）/ 直接回答（直通通道）
> - gate: none
> - blocking: false
```

> 本命令进入 §3.0 时实际触发源是 prev 中的"G0.4.1 bug 意图二次判定（当前需求 bug）"分支。声明头本身保持与 phase-coding.md 真实头一致，不因触发源不同而简化。

后续进入 §3.1~§3.11 各章节时，同样必须先输出对应章节的真实声明头（按 phase-coding.md 各章节顶部复制）。详见 AGENTS.md `G0.5 阶段执行约束（声明式校验）`段。

## 进入回环（仅选 A 或自动判定为「当前需求 bug」时执行）

读取 `{SKILL_DIR}/rules/phase-coding.md`，按 §3.0 → §3.1~§3.11 完整执行：

### §3.0 通道判断
- 仅样式/文案 bug → **快速通道**（§3.1 → 改代码 → §3.9 → §3.10 → §3.11）
- 涉及业务逻辑/接口/数据 → **标准通道**（§3.1~§3.11 完整）
- 仅询问报错原因，不改代码 → **直通通道**（直接回答）
- 不确定 → 触发 G2 停车

### §3.1~§3.8（与正常开发完全一致）
- §3.1 加载规范+铁律、§3.2 加载 spec、§3.3 文档学习、§3.4 影响面评估
- §3.5 代码变更、§3.6 代码审计（S-01~S-08）、§3.7 开发自测
- §3.8 task.md 联动（bug 修复回环不计入 task.md 子任务，跳过）

### §3.9 生成 Changelog
- `.project/changelog/{YYYY-MM-DD}-{xx}-{简述}.md`，标签 `[Bug]`

### §3.10 Spec 状态同步（**bug 修复回环专属留痕**）
- **不新建 REQ/DES**（复用 approved 文档）
- **REQ 末尾追加 Bug 修复记录**：
  ```markdown
  ---
  ### Bug 修复记录 — {YYYY-MM-DD}
  - **现象**: {bug 表现}
  - **根因**: {根本原因}
  - **修复方案**: {修改内容}
  - **验收标准**: {修复后预期行为}
  - **涉及文件**: {文件列表}
  ```
- **DES 标注变更处**：在受影响段落末尾追加 `<!-- Bug fix: {bug 现象简述} {日期} —— {修改说明} -->`
- API 行为变更 → 同步更新 `.outdocs/api-doc.md`
- UI 变更 → 同步更新 `prototype-spec.md`
- 写入 `change-log-specs.md`（操作人: AI，触发源: `[bug-fix-loop]`）

### §3.11 写入 context.md（按原始 last 路由）

| 原始 last | 修复后路由 | context.md last 写入 |
|---|---|---|
| §3.x（§3.0~§3.11） | 回到原始 last 位置继续开发 | `last: {原始 last 值}（bug 修复回环完成，继续原开发流程）` |
| §4 | 重新进入 §4 归档验证 | `last: §3.11 写入 context.md（bug 修复回环完成，下次进入 §4 重新归档）` |

## G1 门禁豁免

bug 修复回环不计入 task.md 子任务，G1 检查项 #5 自动跳过；其他检查项（#1~#4、#6）正常执行。

## 参数

`$ARGUMENTS`（必填或在交互中追问）：bug 现象描述。无描述时 AI 主动询问：
```
【Bug 定位】请描述：
  1. 现象（什么时候发生、看到什么）
  2. 复现步骤
  3. 预期行为 vs 实际行为
  4. 涉及的页面/接口/模块
```
